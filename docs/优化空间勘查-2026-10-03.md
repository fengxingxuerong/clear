## A 类：正确性（已修）

### A1 `[事实]` 带 `g` 标志的正则用 `.test()` 有状态 —— `detector.ts:392`（修前）

`segmentRisk(sent)` 逐句调用 `CONCRETE.test(sent)`，而 `CONCRETE` 带 `g` 标志。
`RegExp.prototype.test` 会读**并写** `lastIndex`，故连续调用交替返回 true/false。

实测（`artifacts/_probe-gflag.cjs`）：同一句"他昨天买了3个苹果。"连判 4 次 → `true, false, true, false`。
**影响**：`segmentRisk` 里"有具体细节 → risk -= 12"这条判据被吞掉约一半句子 → 句级风险分偏高，
`topSegments` 高亮错位（`detectAI` 的 `topSegments` 直接喂 UI 分段高亮）。

修法：改用 `sent.search(CONCRETE) >= 0`（`String.prototype.search` 不读也不写 `lastIndex`）。
已加回归测试（`zhuque-lexicon.test.ts` 第 5 条）。

### A2 `[事实]` 两份特征正则漂移且含死分支 —— `detector.ts:83-97` vs `zhuque.ts:141-148`

5 条正则两份硬编码，`MODAL` 已漂移。逐条核实出的**真实语义**（非"重复"这么笼统）：

| 分叉项 | 事实 | 处理 |
|---|---|---|
| `需要进一步` | **死分支**：交替"首次匹配优先"，前面 `需要` 先命中（实测 `"需要进一步".match(re) === ["需要"]`） | 保留（零行为变化），注释登记 |
| `值得注意的是` | 与 `FORMULAIC:17` 同一处被"套话密度"+"情态密度"各计一次 | 保留（改它会移动 x 轴） |

修法：收拢进 `zhuque-lexicon.ts`，但**刻意保留两个变体**（`reModalDetector()` / `reModalZhuque()`）——
统一会移动 zhuque 的 x 轴打分，而标定漂移棘轮已压满（6/18 点、Δmax 35/35），任何 x 轴移动都会顶红它。
配三道守卫测试：正向（字符级一致）+ 反向（差异只允许那 2 个词）+ 自检（比对逻辑失效也红）。

## C 类：性能（已修，均为等价优化）

### C1 `[事实]` 循环内无条件扫描累积全文 —— `humanize.ts:1031`（修前）

```js
const padBudgetLeft = countPadHeads(out.join(""));        // 无条件先算
const padInjectAllowed = !isAcademic && isCasual && !padForbiddenGenre && padBudgetLeft;
```

`countPadHeads` 扫描"已累积全文"，逐句调用 → O(句数 × 全文长)。
`[事实]` 多段文本不明显（`humanize()` 按 `/\n+/` 分派到 `humanizeSingle`，`out` 只覆盖单段）；
**单段长文**（用户粘一大段不分段）走 `paragraphs.length <= 1` 分支直接全文循环 → 超线性。
实测（`artifacts/_probe-pad-scan3.ts`）：38400 字 / 800 句 **99.8ms**，相邻"每万字 ms"倍率 ×1.58。

修法：把昂贵调用挪到 `&&` 链**末端**。`countPadHeads` 是纯函数、无副作用 → 短路行为完全等价；
默认风格是 `plain`（`isCasual=false`，`store.ts:80`）→ 昂贵调用根本不执行。
`[事实]` 修复后同输入 **20.8ms**（4.8×），倍率回到 ×0.94（线性）。

### C2 `[事实]` 为读一个字段跑整个评分 —— `humanize.ts:809`（修前）

`aiScore(result).burstiness` —— `aiScore` 除句长统计外还要跑 4 组词表全表扫描 + 污染句统计。
实测（`artifacts/_probe-burstiness.ts`，同输入 200 次均值）：15680 字 **1.399ms vs 0.131ms（≈10×）**，
结果逐位相同（等价性已验证）。

修法：新增 `burstinessOf(text)`（`humanize-metrics.ts`），**保留 `toFixed(2)`**——
`aiScore` 返回的是舍入值，直接返回 `cv` 会在 `burstiness < 0.48` 边界上改变行为。

### C3 `[事实]` `llm-humanize.ts:570/594` 对同一 `cand.shuffled` 调两次 `fingerprintCheck` —— **未修**

两处 `if` 条件不同（`:570` 看 `round>=2 && bestText`；`:594` 看 `score !== null`），
只在"修订轮 + 有最优稿 + 评分有效"时同时命中，可合并但收益小（每轮至多省 1 次，
且 `fingerprintCheck` 非热点）。**列为未修**，避免为微小收益改动 API 路径。
