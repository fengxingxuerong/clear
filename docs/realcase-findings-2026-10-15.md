# 真实案例测试报告 · 2026-10-15（本地引擎 · intensity 0.9）

## 为什么要跑这一轮

项目自带的探针体系是很强的：**23 条类别级签名 × 14 体裁语料 × 3 强度档 × 10 种子 = 420 次/探针**。
但它的语料是**模板句**（零修饰的标准句），而历史上每一次拿真实稿件试都能抓出模板没盖住的东西。

本轮的结论也印证了这一点，而且是可量化的：

> 「口语结果动词 + 抽象宾语」这条签名的距离上限从 **6 字放宽到 12 字**之后，
> 模板语料 **仍然零命中**（420 次/探针全绿）；而真实案例第一轮就抓到了
> 「我们需要搞出一个清晰的自我认识体系」——宾语前带 9 字修饰语。
>
> **⇒ 探针放宽之后模板依然测不出，说明这不是"探针不够严"，而是"模板语料的宾语几乎不带修饰语"这一结构性差异。真实语料不是锦上添花，是不可替代的那一层。**

- **A 硬缺陷**（机器说了算，不需要语言直觉）：URL/邮箱/数字/英文专名/代码行丢失、引号不配对、长度失控（-30%/+30%）、占位符残留、黑话泄漏、相邻重复句、空句。

## 已发现并修复（3 项）

### ① 体裁误判：台词冒号把三种非台词形态一起数了进去

`classify-genre.ts` 的 `dlgColonRatio` 用「句首 24 字内出现冒号」判定台词，于是：

| 真实样本 | 冒号性质 | 计入台词 |
|---|---|---|
| 「公司首席执行官王建国在发布会上表示：**"**这款产品…**"**」 | 新闻**转述动词** | ❌ 本不该算 |
| 「接口地址变更为 **https:**//api.example.com/…」 | **URL scheme** 分隔符 | ❌ 本不该算 |
| 「本次 API 升级说明如下：」「调用示例：」 | 说明文标签 | ❌ 本不该算 |

后果不止是标签错：`guardFormalRegister`（坏替身还原层）只在 main / academic 生效 ⇒
API 文档被打成 dialogue 后，替换层打出来的口语/生硬替身**没有任何一层会兜底**。

**修法**（`classify-genre.ts`）：逐项排除这三类，**不碰任何阈值**——动阈值会连带 exposition/narrative 的测试基线。

**效果**：C9 `dialogue → main`、C5 `dialogue → narrative`；C7/C8 仍是 dialogue（真对话体，判定正确）。
全量 **1804 tests / 87 files 全绿**，零漂移。

### ② 坏替身的还原被绑在体裁上 —— 病句与体裁无关

```
原文：该模型通过在大规模语料上进行预训练
产出：该模型借在大规模语料上进行预训练      ← VOCAB「通过→借」，介词用替身、动词替身套回去
产出：明显拔高了下游任务的表现              ← VOCAB「提升→拔高」
```

这两条在 `BROKEN_SUBSTITUTES` 和 `FORMAL_RESTORE` 里都挂了名，但 C3 被判 narrative ⇒ **整层 FORMAL_RESTORE 不跑**，没人管。

**修法**：新增 `fixBrokenCollocations()`（`anti-fingerprint.ts`），**无条件执行**，放在 `guardFormalRegister` 之后。

修的过程中自己也踩了两个坑（都写进注释了）：
- 还原串写成 `"通过$1$2"` 会把原句的「在」吃掉 ⇒ 必须补回「在」得到「通过在…上」；
- 抽象宾语的距离上限照抄常见写法 `{0,4}` 会整条漏网（真实文本"拔高了下游任务的表现"中间 6 字）⇒ 放宽到 `{0,8}`。

**变异检验**：关闭调用 → 端到端用例立刻报红。

### ③ 抽象宾语守卫窗口太窄（6 → 12 字）

生产守卫 `ABSTRACT_OBJECT_RE` 原本 `[\s\S]{0,6}` + `slice(end, end+8)`。
真实案例 C2「搞出**一个清晰的自我认识**体系」宾语前有 9 字修饰语 ⇒ 完全看不见"体系"。

**修法**：窗口 6→12 / slice 8→14，并把**探针与测试副本同步放宽**（项目纪律：探针正则与守卫必须同源）。
放宽方向是"多否决替换"——与「宁可少改，不可错改」同向。

效果：`搞出一个清晰的自我认识体系` → `建立一个清晰的自我认识体系`。
`SCAN_TIER=full` 重跑：**0 违规**（且放宽后模板语料依然零命中，见开头那条结论）。

## 已发现但**未**修复（6 项，附复现）

刻意没有逐词打补丁 —— 这六条的产物大多是 **VOCAB 词表本身的问题**（替身没有标注语体/搭配对象），

## 后续建议（按性价比）

1. **把 `scripts/realcase` 固化成回归**：每次改 VOCAB/守卫都跑一遍 `run.ts`，硬缺陷必须保持 0，且逐个 diff 产出。成本 ~3 秒，比人工抽检可靠得多。
2. **给 VOCAB 加语体标注**（治本）：被标记为"仅限口语体"的替身在 formal 语体下直接不用，
   比在 FORMAL_RESTORE 里多行补一条更靠上游。建议先覆盖高频的 20 条
   （本轮中招的「努力 / 围绕 / 体现 / 协同 / 通过 / 提升」都在其中）。
3. **自问自答注入加体裁门控**：公文/总结/学术摘要下不注入，对话与社媒保留。这条收益明确、改动面比切句小得多。
4. 切句层（第 6 项）暂不动，与既有判断一致。
