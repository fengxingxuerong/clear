# 技术文档：AI 指纹检测与朱雀分映射标定

> 适用版本：v0.7.x-dev　|　代码位置：`src/engine/humanize-metrics.ts`
> 性质：本地启发式自检器 + 人工标定映射。**本项目不调用、不模拟腾讯朱雀官方接口**。

---

## 1. 总体架构

```
┌─────────────────────────────┐
│ 腾讯朱雀（闭源网页服务）        │ ←── 用户手动送检，拿回官方百分比
└──────────────┬──────────────┘
               │ 人工回传数据点 (aiScore, 朱雀%)
               ▼
┌─────────────────────────────┐
│ 标定映射（本文档 §3）          │ ←── 最小二乘拟合，随样本扩充更新
└──────────────┬──────────────┘
               │ 提供换算与阈值预估
               ▼
┌─────────────────────────────┐
│ fingerprintCheck（本地,开源） │ ←── 8 项检查（本文档 §2 与 §5）
│ aiScore（本地代理分）          │
└─────────────────────────────┘
```

设计立场：本地检查是「考前自查清单」，朱雀是「阅卷老师」，两者之间靠人工标定搭桥。
每次真实送检数据回传后，映射的置信度实质上升；若新数据点偏离现有直线，则按体裁分层建模。

## 2. 七项指纹检查规则（fingerprintCheck）

入口：`fingerprintCheck(text: string): FingerprintReport`
返回 `{ pass, issues[], sentenceCV }`，其中每条 issue 含 `name / count / hint`。
**全部检查为确定性实现（无 RNG），同输入必同输出。**

### 2.1 中英数字间空格

- **逻辑**：两个正则计数——`[中文标点][ \t]+[A-Za-z0-9]` 与 `[A-Za-z0-9%）)\]][ \t]+[中文]`
- **阈值**：命中数 > 0 即红
- **依据**：AI 训练语料惯留盘古之白（"共 100 次"），真人中文打字不留

### 2.2 垫词复读

- **逻辑**：遍历垫词词典 PAD_WORDS，统计 `词 + "，"` 出现次数
- **阈值**：同一词出现 > 1 次即红
- **依据**：同一口头禅多次复现是机器复读特征

### 2.3 破折号 / 省略号超标

- **逻辑**：分别统计全文 `——` 与 `……` 出现次数
- **阈值**：各自最多允许 1 个
- **依据**：生成模型对长破折号/省略号的使用频率显著偏离人类习惯

### 2.4 段首过渡词残留

- **正则**：`/(?:^|[。！？!?\n]\s*)(然而|因此|此外|与此同时|综上所述|总而言之|值得注意的是)[，,]?/g`
- **阈值**：命中 > 0 即红
- **依据**：段首逻辑连接词堆叠是 LLM「总-分-总」骨架的直接外显

### 2.5 AI 套话残留

- **逻辑**：与 FORMULAIC 套话词典逐一 `includes` 比对；另查四个高频特征词（值得注意的是 / 毋庸置疑 / 应运而生 / 至关重要）
- **阈值**：任一命中即红
- **依据**：这类词是检测器单点高权重的判别特征

### 2.6 句长节奏过平（突发性 Burstiness 双通道）

> 朱雀官方科普材料点名「困惑度与突发性」两大核心指标；本项即对齐官方口径的突发性检测。

- **通道一（相对判据）**：`sentenceStats()` 计算句长变异系数 CV（标准差/均值），句数 ≥ 4 且 CV < `MIN_BURSTINESS_CV = 0.45` 报警
- **通道二（绝对判据，官方标定值）**：第三方实测数据显示 AI 生成文本的句长标准差通常落在 **5~8 区间**；句数 ≥ 6 且标准差 ∈ [4.5, 8.5] 时报「句长标准差落入 AI 特征带」
- **报告字段**：`FingerprintReport.sentenceStd`（可选字段，向后兼容）
- **依据**：人类写作长短句交错（high burstiness），LLM 输出长度分布过平且集中
- **注**：引擎侧 `boostBurstiness()`（强度 >0.4 时启用）是本项修复器
- **缺口修复**：官方另一核心指标「困惑度」已由第 8 项检查落地——本地 ONNX 小模型的 MLM 伪困惑度近似，详见 §5

来源：朱雀官方功能页（困惑度/突发性表述）、腾讯云社区《朱雀AI检测原理深度解析》（七维度、句长标准差 5~8 实测区间）。

### 2.7 半角逗号过多（反向检查）

- **逻辑**：半角 `,` 占全部逗号的比例
- **阈值**：比例 > 15% 报警
- **依据**：反指纹注入层刻意模拟手滑混入少量半角逗号（控制在 ≤5%）；超过 15% 说明「拟人扰动」过头成了新指纹。此条防止修复手段自身变成把柄

### 2.8 使用方式

```typescript
import { fingerprintCheck } from "./engine/humanize.ts";

const report = fingerprintCheck(outputText);
if (!report.pass) {
  for (const it of report.issues) console.log(it.name + " x" + it.count + "：" + it.hint);
}
```

UI 入口：「指纹体检」按钮；回归套件中同组规则以种子扫描形式长期值守。第 8 项困惑度在同一面板展示，宿主不可用或推理失败时静默降级为仅显前 7 项。

   这种误差会把"必被判 AI"念成"大概率能过"。（修标尺之前 D0 的 x 是 81，旧线反而蒙对了 100%——
   对得准是因为两边用了同一个 bug，不是因为线好。）
2. **论说线（默认线）撑不住**。把 x 换成当前引擎重算的值之后，R² 从 0.98 掉到 0.584、

### 3.3 四条体裁线公式 & 拟合质量

全部使用最小二乘线性拟合，统一 `clamp(y, 0, 100)` 饱和裁剪。

| 体裁线（下拉显示名） | n | 公式：y = 官方朱雀% | R² | S.E. | 饱和下界（x ≥ ? → y ≥ 100%） | 适用场景 |
|---|---|---|---|---|---|---|
| **默认·论说/公告/学术** | 3 | `y = clamp(2.008x + 19.201, 0, 100)` | 0.962 | 6.9 pp | x ≥ 40.2 （即 aiScore > 40 直接判 🔴 必中） | 所有结构化/总分总/三段式文本、期末/职场文书、论文作业提纲等（项目原生体裁）|
| **叙事·散文·小说** | 3 | `y = clamp(1.681x + 20.000, 0, 100)` | 0.998 | 2.3 pp | x ≥ 47.6 | 故事/游记/散文/小说节选/随笔 |
| **对话·剧本·访谈纪要** | 3 | `y = clamp(0.8827x + 26.5, 0, 100)`（2026-09-05 漂移重拟合） | 0.999 | 1.5 pp | x ≥ 83.3 | 对白、聊天记录整理、剧本、角色台词；**因斜率仅 0.88，aiScore 高的对话体判罚比其他体裁更松** |
| **纯人写稿（无 AI）** | 3 | `y = clamp(−0.300x + 18.000, 0, 100)` | 0.750（n=3 无自由度）| — | **不适用**（斜率为负 → 越高越安全） | 【仅对照用】老师/编辑手写原稿，或完全无 AI 参与的文本；**⚠️ 这条线的最重要用途是告诉用户：真人稿别跑去味，见 §3.5.3** |

> 副线（拼接送检专用，不进 UI）：`y = 0.471x + 57.44`（n=3，R²=0.919，截距较论说线高 +38.2 个百分点，完全来自桥接段"人写基底"偏倚）。

### 3.4 v2 分层反推：各体裁"官方朱雀 ≤40%（过人线）"所需 aiScore 阈值表

| 目标官方显示 | 论说/公告 需 aiScore ≤ | 叙事/散文 需 aiScore ≤ | 对话/剧本 需 aiScore ≤ | 纯人写对照（说明）|
|---|---|---|---|---|
| ≤ 30% | 5.4 | 5.9 | **10.1** | （不适用，H0 已经 15% 天然过线）|
| **≤ 40% 过人线** | **10.4** | **11.9** | **20.6** | **天然过：H0 官=15%，**不需要做任何处理** ✅ |
| ≤ 50% | 15.3 | 17.8 | **31.0** | 天然过（即使 x=0 预测也只有 18%）|
| ≤ 60% | 20.3 | 23.8 | **41.4** | 天然过 |
| ≤ 80% | 30.3 | 35.7 | **62.3** | 天然过 |
| 🔴 饱和区（官方基本必判 AI ≥98%）| x ≥ 41 | x ≥ 48 | x ≥ 83 | — |

**关键差异解读**：
- 对话体裁过人门槛是 **aiScore ≤ 20.6**，**比论说线（10.4）放宽近一倍**。原因：对话体天然就是短句、口语、回环往复、你一句我一句，这些"人写统计指纹"天然被朱雀认可；本地 aiScore 对对话体的结构打分偏严，但官方不把它视为 AI 指纹。
- 纯人写线：**任何处理都多此一举**。H0（未去味）= 15% 已稳稳低于过人线 40% 下限约 25 个百分点，属于 ✅ 深绿区。

### 3.5 参数解读 & 本轮 4 项重要发现

#### 3.5.1 之前「通用主线截距 19.2」对纯人写体裁偏高了约 4 个百分点

旧主线以 3 篇论说文拟合，截距 19.2 代表"即使用本地方式让文本全无人写特征，官方仍会给约 19% 的误杀"。但 H0（纯人写无处理，x=10）实际官方只有 15%，并且 H0/H1/H2 三条在 x=0 附近的人写 y 实际值为 15/17/19%，而旧主线 x=0 会预测 19.2%，**系统性高估 0~4 个百分点**。结论：
- 对论说/叙事/对话三类 AI 生成占主导的文本，19.2 的截距**基本合理**（三条独立分线截距分别 19.2 / 20.0 / 20.3，差异 ≤1.1 pp，稳定）；
- 仅对纯人写体裁偏高，但纯人写体裁实际也不用去味，这个偏高不影响实际决策。

#### 3.5.2 同 x=10 档 y 差 30 个百分点（15% → 45%）：体裁选择比 aiScore 数值本身更能决定官分

| 点 | x=10 完全一致 | 体裁 | 官方朱雀% | 用论说分线预测（误）| 实际 |
|---|---|---|---|---|---|
| O2 | 10 | 论说（典型 AI 写的）| 45% | ✅ 39.3（差 5.7）| 高 |
| H0 | 10 | 人写（典型真人写的）| 15% | ❌ 39.3（差 24.3）| 低 |

**根本原因**：aiScore 是"本地是否命中 AI 指纹词表/结构"的打分；而官方朱雀还看**句间连贯性、话题流、用词分布**等更深层特征。同样 aiScore=10 的文本，如果是"真人写的自然句"（H0），官分能比"AI 写了再重排词"的论说文（O2）低整整一倍。这就是为什么 v2 必须分体裁。

#### 3.5.3 ✅ 反直觉验证：纯人写稿越去味 → 官方朱雀分越高

| 点 | 处理 | aiScore | 官方朱雀% | 对比 H0 |
|---|---|---|---|---|
| H0 | **纯人写，完全不处理** | 10 | **15%**（最低 ✅）| 基准 |
| H1 | 纯人写 + 基础档 0.6 去味 | 0（本地认为"更像人"）| 19%（↑ +4%，反而更糟）| 官方判"AI 味"增加 |
| H2 | 纯人写 + 朱雀档 0.9 去味 | 0（本地认为"更像人"）| 17%（↑ +2%，同样变差）| 官方判"AI 味"增加 |

3 点 OLS 斜率 = −0.3（负值）。**原因**：humanize 引擎内的"错别字注入、自问自答注入、连接词拆改"等反检测功能，在**纯人写原稿**上反而会引入"本来人不会写的典型机改痕迹"——朱雀学会了识别这些反检测手段本身。因此结论：

> 🚩 **操作警示**：如果你确认文本是 100% 人写的老师/同学/同事原稿，**不要运行 humanize 引擎**。直接投官方/交作业即可。跑任何去味都会增加被官方判 AI 的概率。

#### 3.5.4 对话体裁斜率仅 0.96 ≈ 论说的一半

对话体 3 点 y/x 比值：D1 饱和（98/81=1.21）、D2 28/6=4.67、D3 25/7≈3.57 → 拟合后斜率 0.959，仅为论说线 2.008 的 **48%**。原因是对白天然具备"短句 + 轮流发言 + 口语词/语气词 + 话题跳动"，这些在论说线里是要"做功破坏"的 AI 指纹，在对话体里本来就是天然的人写指纹。因此：
- 写对话/剧本类作业，对本地 aiScore 的要求可以放宽近一倍；
- 很多本地打分 20 的对话体（论说线会判 🟡 中风险），实际官方 ≤ 40%，完全在 ✅ 过人线；
- UI 新增体裁下拉就是为了给用户显示这种差异。

### 3.6 统计学警示（v2 更新）

- 每条体裁线 n=3，自由度 1；但 v2 的强项是**四条线两两独立验证了截距高度一致（18.0 ~ 20.3，差 ≤2.3 pp）**，不是"同一批样本反复自洽"。
- 对话线饱和下界 x=83，实际作业中很难触达（D1=81 才卡到 98%），对日常使用没影响；
- 论说线饱和下界 x=40，实际 O1 x=33 还没饱和（官 85%），D1 论说 x=81 论说线直接溢出 → UI 要做饱和提示；
- 人写线 n=3、R²=0.75、斜率为负 → 不能做数值外推预测，只用于 §3.5.3 警示显示；
- 所有 v2 点都是**纯单篇（无桥接段）**，可直接用于交付件阈值，不像副线那样带加工偏倚。

## 5. 第 8 项检查：本地困惑度近似（PPL Feature）

> 朱雀官方点名的两大核心指标中，「突发性」由 §2.6 覆盖；本节补上最后一块——「困惑度」。
> 实现方式：本地 ONNX 小模型推理的 MLM 伪困惑度近似，全程离线、文本不出机。
> 设计规格：`docs/superpowers/specs/2026-08-25-ppl-feature-design.md`。

### 5.1 原理与定位

- **方法**：MLM 伪困惑度（Salazar et al., 2019 打分法，分组掩码变体）：把窗内可打分 token 均分为 `MASK_GROUPS = 5` 组轮流掩码——组内替换为 `[MASK]`、组外保留原文，逐组前向取各掩码位 log softmax 后原词分量的负对数似然（NLL，nat），最后按目标数加权平均。若全部位置同时掩码，每个字都近乎失去上下文，NLL 被压向词表熵上限而抹平人机差异；分组保留组外原文作上下文，恢复判别力且成本仅为逐位置打分的 1/K。标点同样参与打分，口径更贴近生成式困惑度。
- **模型**：`Xenova/bert-base-chinese` int8 量化版（约 100MB），默认从镜像站 hf-mirror.com 下载；首次使用一键下载，之后完全离线。
- **判定独立**：作为第 8 项独立检查呈现，不计入 aiScore，不改动 §3 已发布标定映射。
- **设置开关**：设置弹窗新增复选框（默认开启）；关闭后指纹面板仅显示前 7 项。

### 5.2 双通道判定（pplIssues）

| 通道 | 判据 | 初版阈值 | 含义 |
|---|---|---|---|
| 均值通道 | 全文平均 NLL 过低 | < `PPL_MIN_MEAN_NLL`(0.70 nat) 报「困惑度异常低」 | 模型对每个字的走向都太有把握，是生成式行文的典型信号 |
| 平坦通道 | 各窗 NLL 的窗间标准差过小 | 窗数 ≥ `PPL_MIN_WINDOWS`(3) 且 σ < `PPL_MAX_WIN_STD`(0.12) 报「困惑度曲线过平」 | 全文置信度无起伏，对应生成式「全程高置信」 |
| 静默区 | 打分字数 < `PPL_MIN_CHARS`(60) 不判 | — | 短文本样本不足，避免误报 |

滑窗参数：每窗 384 token、步进 320（512 上限扣除 [CLS]/[SEP]/[MASK] 余量）；每窗推理次数 = 掩码组数 K=5；长文按字数加权聚合均值 + 窗间样本 σ。

对齐实现说明：transformers.js v4 不提供 offset_mapping 也未暴露词表，因此选点采用免对齐方案——BERT 的 MLM 打分只需要「token 位置 + 原词 id」，两者天然在 ids 序列里；跳过特殊 token（[PAD]/[UNK]/[CLS]/[SEP]/[MASK]，id 固定）与 UNK 即可，无需字符坐标。该规则在 scorer-core 与 ppl-engine.cjs 双侧镜像；分组掩码（MASK_GROUPS）同样双侧镜像。

阈值初版由 `npx tsx scripts/ppl-calibrate.ts` 在人工写作/AI 生成对照语料上标定：分组掩码下人工组 meanNll ∈ [0.98, 1.35]、AI 组 ∈ [0.18, 0.42]，两组完全线性可分，取间隔中点 0.70 为均值阈值；两组窗间 σ max 均 ≈0.10，平坦阈值取 0.12。随真实分布回传迭代。**诚实声明：当前为小样本自标定（每组 4 篇），误报/漏报率未知，阈值会随数据积累修订。**

### 5.3 分层架构

| 层 | 位置 | 职责 | 说明 |
|---|---|---|---|
| 纯内核 | `src/ppl/scorer-core.ts` | 切窗 / 分组选掩码点 / logsumexp / 聚合 | 零第三方依赖，vitest 用 stub NLL 直测（22 例）；`pplIssues` 判定单测同文件覆盖 |
| 判定 | `src/engine/humanize-metrics.ts` | `pplIssues` 两通道判定 + 阈值常量 | 以 type-only 引用内核，保持零运行时依赖 |
| Electron 宿主 | `electron-app/ppl-engine.cjs` | onnxruntime-node 推理、下载进度、IPC（ppl-status / ppl-download / ppl-score） | 主进程独占原生 CPU 推理 |
| Web 宿主 | `src/ppl/ppl-worker.ts` | WASM 推理 Worker，浏览器 Cache API 缓存 | 与 Electron 共享同一评分内核 |
| 编排 | `src/ppl/ppl-client.ts` | 双宿主探测 / 就绪门控 / 窗口规划与坐标回填 | 渲染层拥有全部策略 |

### 5.4 已知边界

- MLM 伪困惑度不是生成式困惑度本身，绝对数值不可跨模型比较，仅在本项目内做相对判定；
- bert-base-chinese 对古文、诗歌、强领域术语覆盖较弱，这些体裁下第 8 项参考价值下降；
- 模型约 100MB 不打进安装包，首次使用时在线下载（缓存于应用数据目录，之后离线）；
- 免对齐选点规则（跳过特殊 token 与 UNK，id 固定值硬编码）与分组掩码参数（MASK_GROUPS = 5）均在 scorer-core 与 ppl-engine.cjs 双侧镜像，改动必须同步；
- 聚合语义约定：内核 maskedMeanNll 返回"传入目标集的均值"，调用方乘回组大小还原为总和后再除全局目标数，等价于按目标数严格加权——若直接累加会构成双重平均（曾致数值缩小约一个组大小，已在 worker 与标定脚本修复，引擎为内联累加实现不受影响）。
