# 技术文档：AI 指纹检测与朱雀分映射标定

> 适用版本：v0.7.x-dev　|　代码位置：`src/engine/humanize-metrics.ts`
> 性质：本地启发式自检器 + 人工标定映射。**本项目不调用、不模拟腾讯朱雀官方接口**。

---

## 1. 总体架构

```
┌─────────────────────────────┐
│ 腾讯朱雀（闭源网页服务）        │ ←── 用户手动送检，拿回官方百分比
└──────────────┬──────────────┘
               │ 人工回传数据点 (aiScore, 朱雀%)
               ▼
┌─────────────────────────────┐
│ 标定映射（本文档 §3）          │ ←── 最小二乘拟合，随样本扩充更新
└──────────────┬──────────────┘
               │ 提供换算与阈值预估
               ▼
┌─────────────────────────────┐
│ fingerprintCheck（本地,开源） │ ←── 7 项确定性检查（本文档 §2）
│ aiScore（本地代理分）          │
└─────────────────────────────┘
```

设计立场：本地检查是「考前自查清单」，朱雀是「阅卷老师」，两者之间靠人工标定搭桥。
每次真实送检数据回传后，映射的置信度实质上升；若新数据点偏离现有直线，则按体裁分层建模。

## 2. 七项指纹检查规则（fingerprintCheck）

入口：`fingerprintCheck(text: string): FingerprintReport`
返回 `{ pass, issues[], sentenceCV }`，其中每条 issue 含 `name / count / hint`。
**全部检查为确定性实现（无 RNG），同输入必同输出。**

### 2.1 中英数字间空格

- **逻辑**：两个正则计数——`[中文标点][ \t]+[A-Za-z0-9]` 与 `[A-Za-z0-9%）)\]][ \t]+[中文]`
- **阈值**：命中数 > 0 即红
- **依据**：AI 训练语料惯留盘古之白（"共 100 次"），真人中文打字不留

### 2.2 垫词复读

- **逻辑**：遍历垫词词典 PAD_WORDS，统计 `词 + "，"` 出现次数
- **阈值**：同一词出现 > 1 次即红
- **依据**：同一口头禅多次复现是机器复读特征

### 2.3 破折号 / 省略号超标

- **逻辑**：分别统计全文 `——` 与 `……` 出现次数
- **阈值**：各自最多允许 1 个
- **依据**：生成模型对长破折号/省略号的使用频率显著偏离人类习惯

### 2.4 段首过渡词残留

- **正则**：`/(?:^|[。！？!?\n]\s*)(然而|因此|此外|与此同时|综上所述|总而言之|值得注意的是)[，,]?/g`
- **阈值**：命中 > 0 即红
- **依据**：段首逻辑连接词堆叠是 LLM「总-分-总」骨架的直接外显

### 2.5 AI 套话残留

- **逻辑**：与 FORMULAIC 套话词典逐一 `includes` 比对；另查四个高频特征词（值得注意的是 / 毋庸置疑 / 应运而生 / 至关重要）
- **阈值**：任一命中即红
- **依据**：这类词是检测器单点高权重的判别特征

### 2.6 句长节奏过平

- **逻辑**：`sentenceStats()` 计算句长变异系数 CV（标准差/均值）
- **阈值**：句数 ≥ 4 且 CV < `MIN_BURSTINESS_CV = 0.45` 报警
- **依据**：人类写作句长波动大（high burstiness），LLM 输出长度分布过平
- **注**：引擎侧 `boostBurstiness()`（强度 >0.4 时启用）就是针对此项的修复器

### 2.7 半角逗号过多（反向检查）

- **逻辑**：半角 `,` 占全部逗号的比例
- **阈值**：比例 > 15% 报警
- **依据**：反指纹注入层刻意模拟手滑混入少量半角逗号（控制在 ≤5%）；超过 15% 说明「拟人扰动」过头成了新指纹。此条防止修复手段自身变成把柄

### 2.8 使用方式

```typescript
import { fingerprintCheck } from "./engine/humanize.ts";

const report = fingerprintCheck(outputText);
if (!report.pass) {
  for (const it of report.issues) console.log(it.name + " x" + it.count + "：" + it.hint);
}
```

UI 入口：「指纹体检」按钮；回归套件中同组规则以种子扫描形式长期值守。

## 3. aiScore → 朱雀分映射标定

### 3.1 当前映射（v0.7.x-dev，n=1 篇）

**公式：**

```
朱雀% ≈ 2.01 × aiScore + 19.2
```

**标定数据（数字密集型段落：大模型参数/成本/延迟主题）：**

| 文本 | aiScore | 朱雀实测 | 映射预测 | 残差 |
|---|---|---|---|---|
| 原文 | 33 | 85% | 85.5% | −0.5 |
| 本地引擎 强度0.7 | 10 | 45% | 39.3% | +5.7 |
| 深度闭环（ds-v4-flash × glm-5.2） | 8 | 30% | 35.3% | −5.3 |

**拟合质量**：最小二乘，R² = 0.962，r = 0.981，最大残差 5.7 个百分点。

### 3.2 经验阈值表（由映射反推）

| 目标朱雀显示 | 所需 aiScore | 对应能力 |
|---|---|---|
| ≤50% | ≤15 | 本地引擎强度 0.7 已达标 |
| ≤40% | ≤10 | 本地/深度临界区 |
| ≤30% | ≤5 | 需深度闭环进一步压分 |

### 3.3 参数解读

- **截距 19.2 ≈ 噪声地板**：即使 aiScore 压到 0，朱雀分也很难低于约两成。与公开报道的「朱雀对纯人写文本误杀率约 15~20%」吻合——这是检测器本性，不是工具失灵。
- **斜率 2.01 ≈ 持续做功证据**：代理分每降 1 分，朱雀分约降 2 个百分点，说明本地+深度组合对「检测器关心的特征」有稳定的正向作用。
- **深度模式残差为负（实测优于预测）**：结构级重排的收益可能被代理分低估。

### 3.4 统计学警示（必读）

- n=3 点拟合 2 参数仅剩 1 个自由度，R² 高是**小样本的必然体面**；
- 全部数据来自**单篇数字密集型论说文**，不能外推到叙事文、对话体、诗歌等体裁；
- 朱雀版本会迭代，映射参数具有时效性；
- 本映射用于**预估与决策参考**，不构成任何「保证通过」的承诺（README 定位声明同样适用）。

### 3.5 扩充计划

欢迎用不同体裁回传 `(aiScore, 朱雀%)` 数据点：

- ≥3 篇不同体裁 → 给出带置信区间的正式标定；
- 若新点系统性偏离直线 → 按体裁分层建模（叙事线/论说线分开拟合）；
- 数据积累路径已预留：每次人工送检结果可直接追加进本节表格。
