## 一、已知残留病句修复

### 1. "带动"替身病句
- 原：`带动: ["拉着走", "领着"]` → "企业拉着走就业增长" / "领着就业增长" 病句
- 因："拉着走/领着"接宾语仍别扭（"带动产业"是唯一安全搭配，但替身反而破坏）
- 改：**删除"带动"条目**（"带动"本身已口语，保留原词最安全）；"带动了"完成时仍由 GUARD_AFTER 保护

### 2. "落地"叠词病句
- 原："真正落地"→"真正真正做出来"（VOCAB"落地:["真正做出来",...]" + 原文"真正"叠加）
- 改：GUARD_BEFORE["落地"] 加"真正"守卫（"真正落地"不替换）

## 二、deDuplicateOpeners 同主语检测扩展

### 背景
v0.5.10 只处理"主语+动词+了"型（"数字技术改变了教育。数字技术改变了医疗"），漏掉"形容词谓语/值得/是"型同主语复读（"数字化转型很重要。数字化转型很紧迫"——AI 高频指纹）。

### 改动（src/engine/humanize.ts SUBJ_PATTERNS）
新增 3 种模式：
1. `^([2-6字])(?:很|非常|十分|特别|尤为)(?:重要|紧迫|关键|...)` — 形容词谓语型
2. `^([2-6字])(?:值得)(?:关注|重视|...|上心|看重|盯着|留意|当回事)` — 加上 VOCAB 替身词（顺序耦合）
3. `^([2-6字])(?:是)(?:关键|核心|重点|...)` — "是名词"判断型

### 验证
- opt-dup3 6样本×4种子：同主语"数字化转型/数据安全/效率提升/人工智能"全替换→"这/那/它"；异主语"数据隐私/质量提升"不动 ✓
- scan-bugs 全量回归全绿 + opt-stress 250次零病句

## 三、dropLeadingConnectives 删除率提升

- 原概率 `0.35 * (intensity - 0.45)`（intensity=1.0 时仅 0.19，太低）
- 改：`0.55 * intensity`（intensity=1.0 时 0.55，更激进删段/句首缝合词）
- 注意：段落间过渡词（humanize 已按 `\n+` 拆段，每段独立过 humanizeSingle）只能走 replaceOpener 替换路径，dropLeadingConnectives 的删除路径只对段内（句间）生效——设计使然，可接受
