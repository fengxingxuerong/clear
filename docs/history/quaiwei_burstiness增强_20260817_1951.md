## 目标
解决 v0.5.6 遗留的"句长节奏过平"（CV 边界）问题——AI 句子长度均匀是朱雀/知网类检测器的核心指纹。

## 改动（全部在 src/engine/humanize.ts，git diff +263/-68 累计含前几轮）

1. **boostBurstiness 重写为连续劈**：CV<0.45 时最多劈 3 次，每次找当前最长句（≥28 字）在中点 0.3~0.7 逗号劈开，两段均 ≥8 字 + fragmentCanStand 守卫；劈到 CV≥0.45 或劈不动。
2. **切句循环劈句阈值 34→28**：更多中长句可劈，切后两段 ≥8 字防碎片。
3. **fingerprintCheck CV 阈值 0.45→0.4 且句子数 ≥6 才判**：人类短文 CV 0.3~0.4 属正常，<6 句样本 CV 无统计意义（劈句反而触发误报）。
4. **插入语跨句去重**：PARENTHETICALS 已用词不再抽，修"说白了…说白了…"复读（指纹红项）。
5. **boostBurstiness 段落保留修复**：只有实际劈过才 join("")。原无条件 join 丢段落换行，v4.3 段落保留探针抓出 23 次违规——这是本轮最重要的隐性 bug。

## 关键发现（踩坑）
- **劈句是提升 CV 的唯一规则手段，但物理边界**：三句等长短文（18/19/18 字）无 >28 字源句可劈，CV 无法提升——但这类短文句子数 <6，指纹检查不再报红，可接受。
- **CV 检查与劈句的相互作用**：劈句把 4 句变 7 句后触发检查，而 4 句时不检查——逻辑矛盾导致误报，用"句子数 ≥6 才判"解决。
- **段落换行丢失**：splitSentences 把 \n 当句子分隔符并入句子，无条件 join("") 丢段落——必须 changed 才重拼。
