## 三、改动（三处）

### ① CLI `--help` / `-h`（门面修正）

改之前：`--help` 落进参数解析的 `default` 分支 → 打印「未知参数」+ **退出码 1**。

为什么值得动：CLI 是本项目相对 GitHub 同类**唯一没人占的位置**（同类清一色 skill，
只能 `npx skills add`），而 `--help` 是命令行工具的第一个动作、也是 npm 分发后的第一印象。

- `parseArgs` 最前面拦截，**只置位不输出**（parseArgs 是纯函数，vm 沙箱测试依赖这点）；
- 打印放 `main`：走 **stdout**、退出 **0**（帮助不是诊断，不混 stderr）。

测试（进程级 3 条）+ 变异检验（拦截条件改 `false &&` ⇒ 3 条新测试全红、8 条老测试仍绿）。

### ② 覆盖率棘轮收紧：Branch 89 → 91

按 `scripts/coverage-thresholds.ts` 自己的纪律（余量维持 3~5pt、只许单向收紧）：
Branch 余量已漂到 **5.9pt**，越过上限 ⇒ 抬到 91（余量 3.9pt）。
**只动越界的这一项**（Stmt 4.2 / Func 3.7 / Lines 3.7 都还在区间内）。

### ③ 引擎：扩语料池抓到并修掉 2 类残句

按 v0.9.36 的方法论再走一轮：**加语料 → 跑探针（全零）→ 人眼读输出 → 抓病句**。

新加 2 段语料（技术文档 / 操作说明，语料池 8 → 10 段）。同批 **12 条旧探针在新语料上
全部 0 命中**（再一次证明「探针全绿 ≠ 无缺陷」），人眼审读抓到 2 类新缺陷——
两条都是**切点守卫只查一半**的镜像盲区：

| 缺陷 | 实证 | 根因 | 修法 |
|---|---|---|---|
| 介词结构残句 | 18/60：`通过合理配置构建与部署流程，可以有效提高交付质量` → `**用合理配置构建与部署流程。**可以有效…` | **替换在前、守卫在后**：词表先把「通过」换成「用/靠」，而 `ADVERBIAL_HEAD_RE` 只认替换前的「通过」——给替换开了道侧门 | 守卫表补替换后形态（用/靠/借/凭借/基于/依托/经过） |
| 目的从句残句 | 44/60：`…上传至对象存储，以便实现快速回滚` → `**以便做到快速回滚。**` | v0.9.36 的从属从句守卫查 `front`（从句在前），而残句在 **`back`**（从句在后）——只查了一半 | `fragmentCanStand` 补目的连词守卫（以便/从而/以免/以防/借此），与 `SUBORDINATE_LEAD_RE` 形成前后对称 |

- 两条探针同步进 `scan-bugs.ts` v8.0：**14 条 × 10 段语料 × 3 档 × 10 种子 = 300 次/探针全零**。
- 单测各补一组（含对照组）。
- **12 样本棘轮零漂移**（8/0/0/0/0/0/2/2 完全不变）——三处守卫都是纯增量防御，
  不改既有产物行为。

**误判更正**：中途曾把「对话体朱雀档 45 分」误读成 E 组（当前引擎）数字，
实际 45 是 D 组（仓库里冻结的旧引擎产物）的分；E 组当前引擎是 **0**。复核见
`npm run test:regress12` 的 E 组区块。教训：**两组同 id 分数差很大是设计如此**，
读表要看清是哪一组。

## 五、方法论坑（本轮新发现，值得写进肌肉记忆）

**变异检验对「探针与守卫共用同一正则常量」的写法失效。** 第一轮变异把守卫和探针
一起回退（探针通过 import 引用守卫常量），结果是「探针 0 命中」——看起来像探针不敏感，
实际是探针跟着变了。同批独立写表的「目的从句残句」探针则正确报红 30/60。

⇒ 规则：**探针要么独立抄表（可变异），要么明写"与守卫共用、变异检验需单边注入"**。
本轮把「介词结构残句」改为独立抄表后重做变异，正确报红。

代价：守卫表与探针表需手工同步（两处均加了交叉引用注释）。
