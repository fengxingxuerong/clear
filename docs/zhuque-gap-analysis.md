# 趣AI味 vs 真实朱雀 · 差距分析与补全清单

> 更新：2026-09-01（v0.8.2）｜对照对象：matrix.tencent.com/ai-detect 网页版（游客模式实测）
> 结论先行：**表层特征已基本对齐，差距集中在语义/篇章层、隐层特征与官方分校准三处**；
> 本轮把这三处全部接上了"可落地的桥"，但桥不等于对岸——最终仍以官方送检回填为准。

## 一、五层差距对照

| 层 | 真实朱雀 | 本地实现（v0.8.2 前） | 差距 | 本轮补全 |
|---|---|---|---|---|
| 表层特征 | 12 维（词汇分布/句法结构/格式指纹等） | `engine/zhuque.ts` 12 维句级打分 + `engine/detector.ts` 16 特征（2026-09-19 数得；本文 2026-09-01 版写的是 14，此后新增了两项） | 小（阈值已按样本 D 标定） | — |
| 语义/篇章层 | 混元大模型看论点骨架/指代链/因果推进 | 复用通用"检测员"提示词（为去味修订设计，偏表层） | **中**：提示词不对口 | ✅ `api/zhuque-semantic.ts` 专用「朱雀检测员」篇章层提示词（5 维审查：论点骨架/指代链/因果推进/段落节奏/具体性），交叉模型均值/单模型中位数 |
| 隐层特征 | 混元模型置信度（不可复现） | `ppl/` ONNX 困惑度已算出但**未参与检测** | **大**：信号闲置 | ✅ `pplLayerScore` 融合进 `detectZhuque`（权重 0.15 保守；阈值沿用 ppl-calibrate 本地标定：AI 组 meanNll∈[0.18,0.42] / 人工组∈[0.98,1.35]） |
| 官方分校准 | —（官方分即真值） | ①校准实验室需人工攒点（n≥4 才出估计）②BenchmarkPanel v3 四体裁 18 点 OLS **两套校准互不相通** | **中**：朱雀面板看不到已有 18 个官方点拟合的体裁线 | ✅ v3 校准线抽到 `engine/zhuque-calib.ts` 共享；朱雀面板直接显示「体裁线预测」，无需攒点即有官方口径参考 |
| 送检通道 | 网页 ≥350 字、游客可用、无公开 API | 复制送检 + 粘贴回填 + 校准实验室批量流水线 | 小（网页有验证码，自动化不稳，`scripts/` 截图可证） | 维持半自动（这是刻意选择，不做脆弱的页面自动化） |

## 二、当前融合架构

```
                      ┌─ 表层 12 维（zhuque.ts）────────── composite ┐
送检文本 ──┤                                                        ├─ 三档定档 → officialEstimate（回填校准）
                      └─ 困惑度层（ppl ONNX，w=0.15）───────────────┘
                                  +
                      语义层（zhuque-semantic.ts 专用提示词）── fuseLayers(w=0.8 默认，可调/可拟合)
                                  +
                      体裁线预测（zhuque-calib.ts，18 官方点 OLS）── 独立参考线
```

- 三档定档：融合后综合分 ≥40 = AI特征 / ≥20 = 疑似AI / 否则人工特征（官方口径同向，刻度保守）
- 校准双通道：短平快用体裁线（R² 0.77~1.00）；要更准走校准实验室回填（样本越多越贴）

## 三、仍补不了的部分（诚实边界）

1. **混元权重与线上策略不公开**——本地永远只能是"近似器"，判据形态可对齐，刻度只能靠回填校准逼近。
2. **官方分刻度保守**：样本 D 原文本地综合 60.22 vs 官方 99.99%——纯表层方法天然低估；语义层+体裁线就是为此补的。
3. **真值样本量**：目前官方真值仅样本 D 两点 + v3 的 18 点。校准实验室每回填一条，officialEstimate 与语义层权重就重拟一次——这是最值得持续投入的增量。
4. **同分不同因**：本地给不出"为什么是 99.99%"的官方内部依据，只能给 12+1 维可解释特征对照表。
