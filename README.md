# 趣AI味 · QuAiWei v0.8.6

把 AI 写的文章改得更像人写的。**默认不配置任何 API 也能用**（本地引擎离线运行、零成本），
想更强就接一个 OpenAI 兼容的 LLM（各家通吃，实测支持 OpenRouter / SenseNova / OpenAI）。
定位：中文 AI 文本**去味预处理工具 + 送检前自检清单**——可接入朱雀（网页版半自动 / EdgeOne API 全自动）等真实检测器做闭环验证。

> ⚠️ 诚实声明：本项目**不承诺"通过朱雀检测"**——朱雀官方分尚未标定。
> 本地引擎是"换词不换骨"：能削掉套话/标点/空格指纹，但**不打散段落结构和句序**，而结构规律性恰是朱雀等重点特征；
> 真正的结构级去味须走 LLM 深度模式（打散总分总/句序重排/段落重切）。
> 内置评分（本地代理分与 LLM 评判）均为代理指标，与朱雀官方分无标定关系，请以真实检测器结果为准。

## v0.8.6 更新（竞品对标：术语保护 + 批量 CLI + 语义层反指纹维度）

对照 2026 年竞品格局（言笔/笔灵/SpeedAI 等主打"术语零改动"，嘎嘎降AI/零感AI 标配批量处理，

  医学"细胞凋亡"、计算机"机器学习"等），替换引擎在术语位置直接跳过；支持
  `setProtectedTerms()` 注入论文题目/人名/产品名等自定义术语。此前只有事后拦截
  （checkFidelityLocal 查英文术语/数字），现在有事前保护。测试 4 用例。
- **批量 CLI**（`scripts/humanize-cli.ts`）：`npx tsx scripts/humanize-cli.ts <dir> --out <dir>
  --intensity 0.9 --zhuque` 一条命令批量处理 .txt，输出降档对照，竞品标配能力补齐。
- **语义层第 7 维「反检测引擎指纹」**（`api/zhuque-semantic.ts` + `llm-quality.ts` +
  `llm-prompts.ts`）：glm-5.2 实测证明深度改写稿的"刻意口语对仗/自问自答模板/模仿露怯"
  是旧 6 维提示词的盲区——这些恰是引擎自己注入的特征。新维度命中后定向修法表自动
  附"降低人味浓度/拆口语对仗"映射。实测同一样本评分 45→58，痕迹指认更精准。
- **Key 安全改造**（`api/node-keys.ts`）：SenseNova Key 移出源码（环境变量
  `SENSENOVA_KEYS` 或 gitignore 的 `scripts/.sensenova-keys`），浏览器侧预置按钮无 Key 时
  置灰提示。**旧 Key 已随 git 历史泄露，请到商汤后台轮换。**
- **校准体系**：对话线按漂移后 aiScore 重拟合（0.8827x+26.5，R²=0.999）；12 个官方锚点
  完整性守卫进单测，引擎改动导致漂移时 CI 亮红。
- **回归基线**：scan-bugs v5.2/v6.0 WIP 探针 82 次违规全部修零（词表卫生+守卫），
  双档回归全绿。

## v0.8.5 更新（级联守卫复活 + 词表单一事实源 + 连贯性校验 + 调用预算）

- **级联静态守卫复活**：scan-bugs 的级联守卫还在读旧路径 humanize.ts（词表早已迁到
  humanize-vocab.ts），复活后立刻抓出 **19 处真实级联隐患**——替身本身又是另一个键，
  会被后续 pass 二次替换成不可控形态（"紧扣→围绕→钉在"同款）。19 处全部修掉：
  推动/促使/驱动/牵引/立足于/增强/落实/体现 等词条的替身改用非键词
  （如 推动→"推一把"、增强→"强化/变强/加把劲"、体现→"显出/透出/看得出来"），
  现 280 词条替身无一包含其他键。顺带修掉 bestOf 择优探针里
  `FingerprintIssue.level` 不存在的字段引用（指纹本就只报真问题，直接取 issues.length）。
- **检测词表单一事实源**：新增 `engine/zhuque-lexicon.ts`，把 zhuque.ts 与 detector.ts
  各自维护且已漂移的 FORMULAIC/OFFICIAL/SKELETON/CONNECTIVES 四套词表收拢为并集。
  验证：合并后 calibrate-detector 可分性（AI 39 / 真人 21）与样本 D 综合分（60.22）
  **与合并前完全一致**——零分数漂移，纯防漂移收益。
- **连贯性校验**（`coherenceIssues`）：句序重排/段落重切最典型的两类断裂——
  配对衔接词失散（有「其次」没「首先」）与开篇孤代词——确定性检查并入 localHardGate
  喂修复轮；LLM 质检提示词同步补第 3 项「段落衔接」检查。
- **深度闭环调用预算**：`ApiConfig.maxApiCalls`（0=不限）+ 设置弹窗「调用上限」下拉。
  llm-chat 内置逻辑调用计数（重试/换 Key 不重复计），轮间检查、轮内不中断，
  超预算带当前最优结果收场，note 注明实际次数——时间预算之外的计费保护。
- **测试**：185 用例（+5：连贯性 4 + 预算 1）。

## v0.8.4 更新（本地引擎输出质量：反堆叠 / 反复读 / 词表守卫补漏）

对照第一轮实测暴露的三类硬伤（高强度档输出"呣诶嗨咳"堆叠、"是啊。是啊。"复读、
"借对海量数据/对口味学习方案"语义损伤），全部修掉，并新增 `humanize-quality.test.ts`
6 个质量回归用例（30 种子扫描）锁死：

- **锚点反堆叠**（`boostBurstinessInBlock`）：CV 追不上目标时老实现对同一句反复塞
  极短锚，拼出「行对哦诶啊嗯呵呣啧」粒子串。现改为：句尾已有锚点/语气词的句子跳过、
  锚点同块去重、每块总量封顶（2~4 条）。
- **极短句反复读**：管线里 `boostBurstinessIfLow` 会被调用多次（朱雀增强 + P5 清尾），
  每次调用的去重状态互不可见，跨调用仍会挂出「哦。哦。」「是啊。是啊。」。
  现尾部挂锚前实测文本尾 + `boostBurstinessIfLow` 出口兜底清扫相邻同串。
- **词表守卫补漏**（`humanize-guard.ts`）：`通过对N` 的"对"是介词，替身接上去必出
  "借对/靠对"病句——`通过` 后窗口见「对」即跳过；`个性化+方案/学习` 类错配同理。
  `个性化` 替身从「对口味/按个人来」换成「定制化/因人而异的」。
- **反编造对齐**：经验锚点里的「我身边有个朋友…」轶事与 LLM 提示词铁律
  （严禁虚构朋友轶事——检测员重点抓的破绽）自相矛盾，改为第一人称亲历表述。
- **碎片注入去重封顶**（`injectFragments`）：同碎片不再复读、总量约每 3 段最多 1 条。
- **附带收益**：本地引擎改动顺带修复了 scan-bugs WIP 探针 20 处 v5.2 违规
  （546→526），既有稳定探针保持全零。

## v0.8.3 更新（LLM 去味对齐朱雀检测员 + 本地硬门槛 + 表层双判据）

- **深度闭环收敛目标 = 朱雀检测员**：`llm-quality.processCandidate` 的评分阶段改走
  `ZHUQUE_DETECT_SYSTEM`（朱雀语义层提示词）——此前闭环用通用检测员提示词评分，
  优化目标与朱雀抓法脱节；现在"改什么"和"查什么"是同一把尺子，评判痕迹也是篇章层，
  修订轮定向更准。
- **本地零成本硬门槛**：新增 `localHardGate`（指纹体检 + 忠实度校验），LLM 质检放行后
  再过一遍确定性检查，垫词复读/中英空格/破折号超标/数字篡改直接打回修复；
  两条统计型节奏指纹（CV 过平/标准差带）刻意排除在门槛外，避免改写稿被反复打回空烧 API。
- **提示词升级**：主提示词补篇章层 4 条（指代落地/真实取舍/抽象落地/开头结尾反套路）+
  语气词整篇 ≤6 的反表演条目；修订轮按痕迹清单自动附「篇章层定向修法」
  （骨架→重切段落、泛指→落地、并列→加取舍、抽象→给细节等 6 条映射）。
- **朱雀语义层补第 6 维「表演性人味」**：官方对深度改写稿仍实测给 98.47%（样本 D 去味稿），
  抓的正是编造轶事/语气词堆叠/刻意碎句这类伪装痕迹；语义层提示词同步收紧打分口径
  （只做表层润色的改写稿 85+）。
- **朱雀表层句长节奏双判据**：`detectZhuque` 句长节奏维度并入句长标准差绝对判据
  （std∈[4.5, 8.5] 视为落入 AI 特征带，官方口径，与 fingerprintCheck 同阈值）——
  CV 达标但句长集中的文本不再漏判。
- **测试**：新增 `llm-quality.test.ts` 8 个用例（硬门槛打回/统计指纹排除/篇章修法映射/
  闭环走朱雀提示词）+ 句长标准差带用例，全套 174 通过。

## 朱雀实测记录（2026-08-16）

- **最低字数门槛 350 字**：朱雀网页版要求检测文本 ≥350 字，短文本直接报"检测文本长度需大于350字"。
  本工具去味不受影响，但送检前请保证长度；UI 会在文本不足 350 字时给出提示。
- **未登录有次数限制**，且高峰期匿名请求经常「服务超时」/挂起数分钟，建议错峰或登录后使用。
- 匿名会触发滑块拼图验证码（一般自动通过）。
- 本地代理分与官方分的换算尚未标定（本次实测未拿到稳定官方分）。已知定性结论：
  词汇替换类去味对句式骨架无影响，检测模型主要看**结构规律性**（每段开头挂过渡词、
  总-分-总骨架、工整对仗），本地引擎 v0.2 已加入段首过渡词删除等结构级手段。

## SenseNova 网关实测记录（2026-08-16）

用商汤 token.sensenova.cn（OpenAI 兼容）实测 3 Key × 3 模型：

- **三个 Key 均有效**；`sensenova-u1-fast` 在 /models 列表里但 chat 路由 404，**不可用**；
- **`deepseek-v4-flash`：首选**，1.7~2.3s 稳定；`sensenova-6.8-flash-lite`：可用但 2~17s 波动大、偶发空回复；网关另提供 `glm-5.2`、`sensenova-6.7-flash-lite`；
- **CORS 坑**：网关的 OPTIONS 预检返回 404（虽带 Allow-Origin 头），浏览器直连必挂。
  dev 已内置同源代理：设置里 Base URL 填 `/sensenova/v1`（vite.config.ts 里 `/sensenova` → token.sensenova.cn）。
  静态托管/Electron 场景需自备反向代理，或换 CORS 放行的服务商；
- **思考型模型坑**：reasoning 会吃 token 预算，不设 max_tokens 时 content 常返回空。
  llm.ts 已设 max_tokens 并做双保险：评判空 content 回退解析 reasoning 里的数字、去味空输出按失败回退本地引擎；
- 评判波动大（同一文本 20~80），LLM 评判分仅作参考，多测几次取均值更稳。

## 深度去味模式（v0.3.2，LLM 通道）

设置里开启「深度模式」后，LLM 通道走闭环（默认开启）：

```
强化提示词改写 → 标点级机械扰动叠加
      ↑                │
   定向修订 ← 痕迹清单 + 交叉集成评分（未达标>10 才继续）   （最多 4 轮，全程保留最低分版本）
```

- **交叉评判（v0.3.2）**：设置里"评判模型"填一个不同家族的模型（SenseNova 网关推荐 `glm-5.2`），
  主模型+交叉模型各一票取均值，消除自评偏差。实测同一去味文本：deepseek 自评 30、glm-5.2 评 4——
  尺子不同结论天差地别，交叉是当前最稳的折中；
- **质检关（v0.4.2）**：每轮改写先过"通顺+忠实"质检（对照原文查数字/事实/逻辑/编造/语病），不过关自动打回修复一次、再不过弃用该轮；全部轮次质检失败则回退本地引擎。best-of 只收质检通过的版本。改写铁律新增"数字/日期/专名原样保留，禁模糊化"（占40%≠占大头，明年3月≠开春）；
- **痕迹评判**：评判员先列出残留 AI 痕迹（含"虚构人物事例""口语化模仿痕迹"这类高级破绽）再打分；
- **定向修订**：下一轮只动痕迹指出的地方，不推倒重来（防"改过头反弹"）；
- **机械扰动 + 反指纹规则层（v0.3.3）**：每轮结果叠加标点扰动，并做确定性限额/去重——
  垫词去重（说真的/讲真/所以说等 16 个只许出现一次）、破折号/省略号整篇限 1、
  句首过渡词去重、句长变异系数过低时安全劈句（带无主句守卫）。
  全部规则零语法风险，回归测试覆盖（`npm run test:regress` 反指纹段 20 种子）；
- **限流自愈**：429/5xx 指数退避重试；单轮失败保留已有最优结果，不丢工作；
- **实测成绩（不同评判宽严差异很大，如实记录）**：
  - 宽松评判（早期提示词）：原文 ~80 → 输出 10~45
  - 严格评判（含口语模仿痕迹检查）：原文 90~95 → 输出 58~78
  - 交叉评判单次抽查最好：输出 4~5（glm-5.2 / 6.7-flash-lite 各自独立给出）
  - **诚实结论：改写质量已到"人读自然"水平，数字高度依赖评判员宽严；权威结论待朱雀实测**
- 耗时：未配交叉评判约 1~3 分钟；配 glm-5.2（单次 15~20s）约 3~6 分钟。

## aiScore → 朱雀分初步标定（v0.7.x-dev，样本 n=1）

2026-08 首次真实标定：数字密集型段落（大模型参数/成本/延迟主题），朱雀网页版人工实测。

| 文本 | aiScore（代理分） | 朱雀实测 | 线性映射预测 |
|---|---|---|---|
| 原文 | 33 | 85% | 85.5% |
| 本地引擎 强度0.7 | 10 | 45% | 39.3% |
| 深度闭环（ds-v4-flash × glm-5.2） | 8 | 30% | 35.3% |

**线性映射：朱雀% ≈ 2.0 × aiScore + 19.2**（最小二乘，R²=0.962，最大残差 5.7pp）

经验阈值（由映射反推）：

| 目标朱雀分 | 所需 aiScore |
|---|---|
| ≤50% | ≤15 |
| ≤40% | ≤10 |
| ≤30% | ≤5 |

诚实声明：

- **截距即噪声地板**：19.2% 与朱雀对纯人写中文文本的已知误杀底线（约 15~20%）吻合——意味着即使 aiScore 压到 0，朱雀分也很难低于两成，这不是工具失灵而是检测器本性；
- 斜率 ≈2.0：代理分每降 1 分，朱雀分约降 2 个百分点，说明本地+深度组合对"检测器关心的特征"确实在持续做功；
- **样本仅 1 篇单一体裁，以上全部数值为暂定**。欢迎用不同体裁（叙事文/口语对话/学术段落）回传更多 (aiScore, 朱雀%) 数据点，扩充到 3 篇以上即可给出带置信区间的正式标定。
